Ты — senior full-stack инженер. Создай законченный проект: сайт-портфолио, который автоматически строится по GitHub-профилю. Бэкенд на Rust, деплой через Docker.

## Цель
Сайт показывает профиль GitHub-пользователя и его репозитории. Новые репозитории, созданные в профиле, появляются на сайте автоматически, без ручного редактирования и без пересборки.

## Стек
- Бэкенд: Rust (stable), axum, tokio, reqwest (rustls), serde, tracing, tower-http (compression, CORS, trace). Шаблоны: askama или maud (SSR), либо JSON API + лёгкий фронтенд на чистом HTML/CSS/JS без тяжёлых фреймворков.
- Данные: GitHub REST API v3 (`/users/{user}`, `/users/{user}/repos`, `/repos/{owner}/{repo}/languages`, опционально README).
- Деплой: Docker (multi-stage) + docker-compose.

## Функциональные требования
1. **Профиль**: аватар, имя, bio, локация, ссылки (blog, twitter, company), число подписчиков и репозиториев, ссылка на GitHub.
2. **Репозитории**: название, описание, основной язык, звёзды, форки, topics, дата последнего обновления, ссылка на репозиторий и homepage (если есть).
3. **Динамическое обновление**:
   - Фоновая задача (tokio) опрашивает GitHub API каждые N минут (`REFRESH_INTERVAL_SECS`, по умолчанию 300).
   - Используй условные запросы (ETag / If-None-Match), чтобы экономить rate limit.
   - Результат хранится в кэше в памяти (`Arc<RwLock<...>>`) и опционально сохраняется на диск (JSON), чтобы после рестарта сайт сразу отдавал данные.
   - При ошибке API или исчерпании лимита отдаётся последний успешный кэш, ошибка логируется.
   - Фронтенд сам подтягивает свежие данные (периодический fetch к `/api/repos` или SSE) и обновляет список без перезагрузки страницы.
   - Добавь защищённый эндпоинт `POST /api/refresh` (токен в заголовке) для принудительного обновления.
4. **Фильтрация и сортировка**: по языку, по topics, поиск по названию/описанию; сортировка по звёздам, дате обновления, названию. Форки и архивные репозитории по умолчанию скрыты (настраивается через env).
5. **Закрепление и скрытие**: через env или конфиг-файл можно задать список pinned-репозиториев (показываются первыми) и список исключённых.
6. **Статистика**: диаграмма использования языков по всем репозиториям (на основе `/languages`, с кэшированием).
7. **Эндпоинты**: `GET /` (страница), `GET /api/profile`, `GET /api/repos`, `GET /health`.
