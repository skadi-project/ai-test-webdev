# GH/FOLIO

Готовое портфолио, которое собирается из публичного GitHub-профиля. Rust + axum отдают JSON API и лёгкую HTML/CSS/JS-страницу. Новые репозитории появляются после фоновой синхронизации — редактировать код или пересобирать образ не нужно.

## Возможности

- Профиль: аватар, имя, bio, локация, компания, сайт, Twitter, подписчики и число репозиториев.
- Карточки репозиториев с описанием, языком, звёздами, форками, topics, датой и homepage.
- Поиск, фильтры по языку/topic и сортировка по звёздам, обновлению или названию.
- Закрепление и исключение репозиториев, скрытие форков и архивов через переменные окружения.
- Диаграмма языков по данным `GET /repos/{owner}/{repo}/languages`.
- Пагинация GitHub (100 репозиториев на страницу), ETag/`If-None-Match`, ограниченная параллельность запросов языков.
- Снапшот в `Arc<RwLock<…>>`, JSON-кэш на диске, последний успешный снапшот при ошибках и rate limit.
- Автообновление фронтенда каждые 60 секунд и защищённый принудительный refresh.
- Светлая/тёмная тема, адаптивность, skeleton/empty/error-состояния, семантика и keyboard focus.
- Graceful shutdown, structured logs, gzip, CORS, Docker healthcheck и non-root runtime.

## Дизайн-концепция

**Developer field notes**: сочетание редакционной вёрстки и технического журнала. Тёплый бумажный фон в светлой теме сменяется глубоким зелёно-графитовым в тёмной. Мятный/изумрудный акцент обозначает действия и «живой» статус, лаймовый — небольшие акценты. Крупный системный sans-serif используется для имени и заголовков, системный monospace — для индексов, метаданных и названий проектов. Тонкая сетка и номера секций добавляют инженерный характер. Внешние шрифты, трекеры и фронтенд-зависимости не загружаются.

## Требования

- Rust stable 1.85 или новее (для локального запуска).
- Docker с Compose v2 (для контейнерного запуска).
- Публичный GitHub-профиль. Токен не обязателен, но рекомендуется.

## Локальный запуск

```bash
cp .env.example .env
# Windows PowerShell: Copy-Item .env.example .env
# В .env обязательно измените GITHUB_USERNAME.
cargo run
```

Откройте <http://localhost:8080>. При первом запуске данные появятся после первого успешного обращения к GitHub. Локальный кэш сохраняется в `data/cache.json`.

Логи настраиваются стандартной переменной `RUST_LOG`, например:

```bash
RUST_LOG=info,github_portfolio=debug,tower_http=debug cargo run
```

## Docker

```bash
cp .env.example .env
# Установите GITHUB_USERNAME и, желательно, GITHUB_TOKEN в .env.
docker compose up -d --build
docker compose logs -f portfolio
```

Сайт доступен на `http://localhost:${HOST_PORT:-8080}`. Именованный volume `portfolio-cache` сохраняет `/data/cache.json` между перезапусками и пересозданиями контейнера. Внутри контейнера порт всегда 8080; `HOST_PORT` меняет только внешний порт.

Остановка:

```bash
docker compose down
# Удалить также кэш: docker compose down -v
```

Dockerfile использует `cargo-chef`: слой скомпилированных зависимостей переиспользуется, пока не изменились `Cargo.toml`/`Cargo.lock`. Финальный образ — `debian:bookworm-slim`, процесс работает от UID 10001, корневая ФС в Compose доступна только для чтения.

## Конфигурация

| Переменная | По умолчанию | Описание |
|---|---:|---|
| `GITHUB_USERNAME` | — | **Обязательная.** Имя публичного GitHub-пользователя. |
| `GITHUB_TOKEN` | пусто | Токен повышает rate limit. Достаточно fine-grained token с чтением публичных данных; приватный доступ не нужен. |
| `REFRESH_INTERVAL_SECS` | `300` | Пауза между фоновыми синхронизациями, больше нуля. |
| `PORT` | `8080` | Порт локального HTTP-сервера. В Compose внутри принудительно `8080`. |
| `ADMIN_TOKEN` | пусто | Включает `POST /api/refresh`. Без него принудительное обновление отключено. |
| `PINNED_REPOS` | пусто | Имена через запятую. Показываются первыми в заданном порядке; регистр не важен. |
| `EXCLUDED_REPOS` | пусто | Полностью исключаемые имена через запятую; регистр не важен. |
| `SHOW_FORKS` | `false` | Показывать форки. Поддерживаются `true/false`, `1/0`, `yes/no`, `on/off`. |
| `SHOW_ARCHIVED` | `false` | Показывать архивные репозитории. |
| `CACHE_PATH` | `data/cache.json` | Путь к JSON-снапшоту. `none` отключает дисковый кэш. В Compose — `/data/cache.json`. |
| `CORS_ALLOW_ORIGINS` | пусто | Origin через запятую, например `https://example.com,http://localhost:3000`; `*` разрешает все. Пусто — только same-origin. |
| `HOST_PORT` | `8080` | Только Compose: внешний порт сайта. |

Изменения `.env` применяются при перезапуске процесса/контейнера. Сами репозитории для этого менять или пересобирать не нужно.

## API

Все успешные data-эндпоинты возвращают envelope:

```json
{
  "data": {},
  "updated_at": "2026-11-24T12:00:00Z"
}
```

### `GET /api/profile`

Возвращает профиль GitHub. Если первичная синхронизация ещё не удалась и дискового снапшота нет — `503`.

### `GET /api/repos`

Возвращает уже отфильтрованный по env список. Поддерживает query-параметры:

| Параметр | Значение |
|---|---|
| `q` | Поиск без учёта регистра по имени и описанию. |
| `language` | Точное совпадение основного языка без учёта регистра. |
| `topic` | Точное совпадение topic без учёта регистра. |
| `sort` | `stars` (по умолчанию), `updated`, `name`. |

Пример:

```bash
curl "http://localhost:8080/api/repos?language=Rust&topic=cli&q=tool&sort=updated"
```

Pinned-репозитории остаются первыми при любой сортировке. Внутри pinned/обычной группы применяется выбранный порядок.

### `GET /api/languages`

Дополнительный эндпоинт для диаграммы. Возвращает массив `{ name, bytes, percentage }`, отсортированный по числу байтов. Статистика включает все полученные репозитории, кроме `EXCLUDED_REPOS`, включая скрытые форки/архивы.

### `POST /api/refresh`

Принудительно запускает ту же синхронизацию, что и фоновая задача. Параллельные запросы сериализуются mutex'ом. Токен передаётся одним из способов:

```bash
curl -X POST http://localhost:8080/api/refresh \
  -H "X-Admin-Token: $ADMIN_TOKEN"
# Или: -H "Authorization: Bearer $ADMIN_TOKEN"
```

Неверный токен — `401`, отсутствующий `ADMIN_TOKEN` — `503`. Не встраивайте admin token в браузерный JavaScript.

### `GET /health`

Liveness endpoint для Docker:

```json
{"status":"ok","cache_ready":true,"updated_at":"2026-11-24T12:00:00Z"}
```

Возвращает `200`, даже если начальный GitHub-запрос ещё выполняется; готовность данных отражает `cache_ready`.

### Статика

`GET /` отдаёт страницу, `/assets/app.css`, `/assets/app.js`, `/assets/favicon.svg` — встроенные в бинарник ресурсы. Неизвестные маршруты возвращают JSON `404`.

## Обновление и устойчивость к ошибкам

1. После запуска и далее после каждой паузы `REFRESH_INTERVAL_SECS` выполняется синхронизация.
2. Профиль, каждая страница репозиториев и каждый `/languages` имеют собственный ETag в памяти. При `304` используется предыдущее значение.
3. Профиль и список репозиториев собираются в рабочую копию. Ошибка этих запросов прерывает commit, поэтому API продолжает отдавать прежний полный снапшот.
4. Ошибка языков одного репозитория логируется отдельно; для этого языка сохраняется прошлое значение, а свежие профиль/репозитории всё равно публикуются.
5. Успешный снапшот атомарно заменяется в памяти и затем сохраняется на диск. На Unix запись выполняется через временный файл и rename; на Windows существующий файл предварительно заменяется.
6. Ошибка записи дискового кэша не отменяет уже опубликованный in-memory снапшот.
7. При рестарте дисковый снапшот сразу доступен. ETag не сохраняются, поэтому первая синхронизация после рестарта безопасно запрашивает полные данные.

GitHub обычно не списывает корректные conditional `304` из primary rate limit. Без токена лимит небольшой; для профиля с большим числом репозиториев настоятельно рекомендуется `GITHUB_TOKEN`.

## Проверка качества

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test
```

Тесты используют заранее подготовленные ответы GitHub в `tests/fixtures/*.json`: парсинг профиля, репозиториев и языков, нормализацию пустых строк, фильтрацию, pinned/excluded, поиск и сортировку. Сеть в тестах не нужна.

## Структура

```text
src/
  cache.rs       # in-memory/disk snapshot и ETag-совместимые данные
  config.rs      # env и валидация
  error.rs       # единый AppError и HTTP errors
  github.rs      # GitHub REST, conditional GET, пагинация ресурса
  models.rs      # API/domain models
  refresh.rs     # фоновая синхронизация и language aggregation
  repository.rs  # предпочтения, фильтры и сортировка
  routes.rs      # axum routes, middleware и авторизация refresh
  state.rs       # shared application state
  lib.rs/main.rs # сборка приложения и lifecycle
static/          # встроенные HTML/CSS/JS/SVG
 tests/          # fixtures и интеграционные тесты
```
